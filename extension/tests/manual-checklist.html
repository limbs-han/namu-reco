나무위키 개인화 추천 v10 — E1~E14 실브라우저 수동 검증

명세 §5 확장프로그램 수용 기준. 코드 레벨 검증이 있는 항목은 초록 박스로 표기(node --test extension/tests/logic.test.js extension/tests/content.test.js) — 그래도 실브라우저 판정이 규범이다. 입력은 자동 저장되며, 완료 후 「검증 기록 다운로드」로 JSON을 받아 review/에 커밋한다.

0. 사전 준비 (공통)

  1. chrome://extensions → 우측 상단 「개발자 모드」 켜기 → 「압축해제된 확장 프로그램을 로드합니다」 → 저장소 extension 폴더 선택.
  2. 확장 카드의 「서비스 워커」 링크 클릭 → SW DevTools. 「Application」 탭 → Storage → IndexedDB → namu_reco. IndexedDB 화면은 자동 갱신되지 않는다 — 확인 전마다 새로고침(⟳) 아이콘을 누를 것.
  3. 미니배치를 기다리지 않고 당기려면 SW 콘솔에서: 
    chrome.alarms.create("minibatch", { periodInMinutes: 5, when: Date.now() + 1000 })
    (1초 뒤 발화, 이후 5분 주기 유지 — 테스트 전용 조작임을 기록에 남길 것)
  4. 주의: 배포 전이면 SHARD_BASE 원점이 404다 — E8·E10·E11은 gold 배포(또는 로컬 정적 서버로 common.js의 SHARD_BASE 임시 변경) 후 수행.

E1 — view 단위 upsert (5문서 = 5행, dwell ±10%)

  1. IndexedDB에서 events를 비운 상태로 시작(우클릭 → Clear).
  2. 나무위키 문서 5개를 각각 다른 체류시간(예: 35초/70초/100초/130초/160초 — 30초 heartbeat를 넘기도록)으로 열람하고, 각 문서마다 다른 문서로 이동해 이탈을 만든다.
  3. 판정: events에 정확히 5행(heartbeat가 행을 늘리지 않음), 각 행 dwell_ms가 실측 체류시간 대비 오차 ±10% 이내, ended=1.

E2 — 백그라운드 dwell 미포함

  1. 문서 X를 연 뒤 즉시 다른 탭으로 전환해 5분 방치.
  2. X 탭으로 돌아와 10초 머문 뒤 이탈.
  3. 판정: X 행의 dwell_ms가 백그라운드 5분을 포함하지 않음(≈10초 + 전환 전 구간).

E3 — idle 알람 비용 상한

  1. 전제: 처리 대상 이벤트 0건(모두 processed=1), kv.dirty 없음, kv.popular 채워짐, kv.last_prune이 24h 이내.
  2. SW DevTools Network 패널을 연 채 알람 발화(§0-3)를 관측.
  3. 판정: fetch 요청 0건, 추천 재계산 없음(recommendations의 computed_at 불변). 허용 예외: 콜드스타트(popular 부재) fetch 1회 / dirty 시 rebuild 1회(E12) / last_prune 24h 경과 시 prune 1회.

E4 — 캐시 150MB LRU

로직 레벨: logic.test.js「E4 로직: LRU 퇴출」·상수 150MB 검증 통과.
  1. SW 콘솔에서 가짜 대형 샤드를 주입해 총량을 150MB 초과시킨다: 
    for (let i = 0; i < 8; i++)
  await db.txn(["nbr_cache"], "readwrite", tx => tx.put("nbr_cache",
    { shard_id: 9000 + i, payload: {}, version: null,
      size_bytes: 25 * 2**20, last_used: i }));   // §4.5 정의의 해제 후 바이트 회계
  2. 신규 이벤트 1건을 만들고(아무 문서 열람·이탈) 알람 발화 → evictCache 경유.
  3. 판정: nbr_cache의 size_bytes 합 ≤ 150MB, last_used 오래된 행(작은 값)부터 삭제됨.

E5 — 리로드 후 유지

  1. profile·recommendations에 데이터가 있는 상태에서 chrome://extensions → 확장 새로고침(⟳).
  2. 판정: IndexedDB의 profile/recommendations가 그대로, 팝업 표시 정상.

E6 — 링크 폴백 + 유령 제목/비본문 오염 차단

로직 레벨: content.test.js — pathname 기준 선별·URIError skip·네임스페이스 제외·중복 제거·상한 40·컨테이너 LCA. 실브라우저에서 실DOM 판정이 규범.
  1. 전제: 깨끗한 신규 프로필(§0에서 IndexedDB 전체 Clear 후 시작).
  2. gold 샤드에 없는 제목(2021년 이후 신설 문서)을 충분히(수 분) 열람 후 이탈.
  3. 판정 1: 예외 없이 local_nbr에 그 문서의 links 저장.
  4. 알람 발화 → 판정 2: 그 링크들이 recommendations에 source='fallback', sim=0.4 행으로 존재.
  5. 판정 3 [H3]: 열람 페이지 본문에 문단 링크(/w/X#s-2)·query 링크 (/w/X?from=Y)가 있는 상태에서 local_nbr에 X가 정확히 1건 — X#s-2류 유령 제목 0건.
  6. 판정 4 [J4]: 사이드바(최근 변경·인기 문서)에만 노출된 제목이 links에 유입되지 않음.

E7 — 감쇠 검증 (14일 → 1/4)

로직 레벨: logic.test.js「E7 로직」·「[M2] 점화식」 통과.
  1. SW 콘솔에서 profile 행 하나의 last_seen을 14일 전으로 조작: 
    await db.txn(["profile"], "readwrite", async tx => {
  const r = await tx.get("profile", "문서제목");
  r.last_seen -= 14 * 86400000; await tx.put("profile", r); });
  2. 신규 이벤트 1건 후 알람 발화 → 추천 재계산.
  3. 판정: 그 문서 기여의 유효 가중치가 조작 전의 1/4 (±5%) — 기여 추천 행의 score 변화로 간접 확인.

E8 — 콜드스타트

  1. 확장 제거 후 재설치(빈 profile). 첫 알람 발화까지 대기(§0-3 가능).
  2. 판정: popular.json 상위 문서가 recommendations에 노출, reason_title=null, source='popular' — 이벤트 0건이어도 성립. 오프라인 설치면 네트워크 복구 후 다음 알람에서 성립(자가 치유).

E9 — 네임스페이스 차단

로직 레벨: content.test.js「E9 로직」 통과 (대문 view 불가·Re:제로 오탐 없음).
  1. 일반 문서 X 열람 중 나무위키:대문으로 이동해 5분 체류.
  2. 판정: events에 대문 행 0, local_nbr에 대문 미기록, X의 view는 정상 마감(ended=1, dwell이 대문 체류를 포함하지 않음 [I8]), 추천·콜드스타트 목록에 콜론 네임스페이스 제목 없음.

E10 — 정상 경로 (샤드 조회 비강등)

  1. 전제: 깨끗한 신규 프로필 + gold 배포 상태.
  2. popular.json 상위 문서 1건만 열람·이탈 → 알람 발화.
  3. 기대 샤드 id를 검증 대상이 아닌 Python 레퍼런스로 별도 계산: 
    python -c "import sys; sys.path.insert(0,'etl'); \
import importlib.util; s=importlib.util.spec_from_file_location('j','etl/jobs/05_build_shards.py'); \
m=importlib.util.module_from_spec(s); s.loader.exec_module(m); print(m.fnv1a32('문서제목')%1024)"
  4. 판정: (a) nbr_cache에 그 샤드 1건 적재(id 일치), (b) 이웃이 source='shard', sim≠0.4 행으로 기여, (c) 그 행들의 reason_title=방문 문서. source='fallback'으로 관측되면 어느 단계든 침묵 강등 — FAIL.

E11 — 배포 purge 후 비강등

  1. 전제: profile 채워짐 + 후보 정상 산출 상태(프로필 상위 문서가 샤드에 실존).
  2. SW 콘솔: await db.kvSet("manifest_version", -1) (배포 모사 — purge 트리거 검증).
  3. 신규 이벤트 1건 이상 만든 뒤 알람 발화.
  4. 판정: (a) purge 발화 — nbr_cache 비워지고 kv.popular 삭제, kv.dirty·kv.last_prune 보존 [I4], (b) 그 사이클 rebuild 정상, (c) 다음 알람에서 kv.popular 재적재, recommendations가 source='popular' 전량 교체로 덮이지 않음(개인화 행 유지).

E12 — 마킹 후 크래시 복구 (dirty)

  1. SW 콘솔: await db.kvSet("dirty", 1) (마킹 직후·rebuild 이전 크래시 모사), recommendations는 구버전 그대로 둔다.
  2. 신규 이벤트 0건인 상태로 알람 발화.
  3. 판정: prefetch→rebuild 수행, kv.dirty 해제, recommendations의 computed_at 갱신.

E13 — SPA 경로 스코프

로직 레벨: content.test.js「E13 로직」 통과 (비-/w/ 유령 제목 차단).
  1. (a) /w/X 열람 중 사이트 로고로 대문(/) 소프트 전환 → events에 "/"류 유령 제목 0행, X는 정상 마감.
  2. (b) 주소창에 namu.wiki 입력해 대문 최초 진입 → /w/Y로 소프트 전환 → Y의 view가 정상 시작·수집 (matches가 /w/* 한정이면 여기서 실패).
  3. (c) [J3] (a) 전환 후 X의 local_nbr에 대문·차기 문서에만 있는 링크가 유입되지 않고 X 본문 링크가 유지됨.

E14 — 고아 콘텐츠 스크립트 정지

  2. 판정: 기존 탭에서 (a) uncaught 예외가 반복 적재되지 않음(console.warn 1회 허용), (b) 이후 폴링·heartbeat 발화 없음 — 1분 이상 관측(수집 정지), (c) 탭 새로고침 후 새 view 정상 시작·수집.

E16 — SPA 재렌더 생존

  1. 문서 A → 문서 B 소프트 전환(본문 링크 클릭) 후 1초 이내 탭 재출현, 대문 전환에서도 동일.
  2. 판정: 탭 중복 주입 0건(요소 검사에서 #namu-reco-tab 1개), 전환 시 열린 패널 정리.

E17 — 드롭다운 동작

  1. 탭 클릭 → 특수 기능 스타일의 드롭다운에 recommendations가 rank순으로 제목+사유와 함께 표시.
  2. 빈 상태(추천 0행)면 안내 문구 표시. 바깥 클릭 시 닫힘.
  3. 항목 클릭 → 해당 문서로 이동. 특수 제목(C#·A/B)이 추천에 있으면 정확한 문서로 이동.

E18 — 미발견 환경 무해성

  1. 메뉴바가 없는 변형 화면(모바일 레이아웃 폭으로 축소 등)에서 예외 0건, 페이지 기능 무영향, 콘솔 warn 최대 1회.
  2. 판정: 이 경우에도 확장 아이콘 팝업은 정상 동작(폴백 유지).

E20 — 연관 데이터(본문 링크)·미보유 처리 (v0.5.0)

  1. 아무 문서(기존·신설 동일) 열람 → 2~3초 내 본문 내부 링크 상위 10개가 행으로 표시, 행 클릭 → 해당 문서로 이동. 네트워크 요청 0건(DevTools Network에서 확인 — SW 경유·샤드 fetch 없음, 오프라인에서도 동작).
  2. 본문에 내부 링크가 없는 문서 → 박스 미표시, 예외 0건. 자기 자신(목차 앵커 유래) 행 없음.
  3. 대문·네임스페이스 문서(나무위키:대문) → 박스 없음.
  4. 박스에 자동 새로고침 진행바(회색 바) 잔재 없음. 스크롤을 내리면 박스가 top 12px에 고정되어 따라옴(sticky), 좁은 창(반응형)에서는 미적용이어도 무해.

E21 — 전환 갱신

  1. 문서 A → 문서 B 소프트 전환 → 1초 내 박스 내용이 B의 이웃으로 교체(A의 이웃 잔존 0).
  2. 빠른 연속 전환(A→B→C) 후 최종 화면의 박스가 C의 이웃과 일치(늦게 도착한 응답이 덮어쓰지 않음).
